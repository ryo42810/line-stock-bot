# line-stock-bot

日本株の「今日の注目株」を毎朝LINEに届け、X（旧Twitter）用の下書きと画像を作って自動投稿するbot。
GitHub Actions で毎日動く。サーバーは不要。

## できること

### 朝（毎日 6:43 JST を目標に開始）
- **注目銘柄の選定（5〜15件）**：Yahoo!ファイナンス（トップ・注目／値上がり／値下がりランキング）、TDnet（適時開示）、決算予定・優待ランキングのページを読み、AIが選ぶ
  - 分類：好材料／懸念材料／決算（今日発表）／優待（今月・来月が権利確定月）
  - 今日の決算発表予定は、JPX（日本取引所グループ）が公開している予定表（Excel）から読む
- **買い場候補👀（最大5件）**：ルールで機械的に選び、AIが注目理由を添える
  - 好材料の開示が前営業日の引け後に出たのに株価が未反応（前日比 -2〜+3%）
  - 上昇トレンド中の押し目（25日線から -5〜-15%、75日線が上向き）
  - 株価は横ばいなのに出来高が20日平均の2倍以上
  - 優待の権利確定月の1〜2ヶ月前
- **LINEのカード**：地合い（日経平均・ドル円・NYダウ・ナスダック・S&P500）＋銘柄ごとに株価・前日比・利回り（配当＋優待）・優待内容・権利付き最終日までの営業日数・出来高急増／年初来高値安値／25日線乖離
- **X下書き**（本文だけ送るのでそのままコピペできる）：平日はくじら枠（下の表）、日曜はアンケート版
  - ニュース版・買い場候補版のX投稿は、くじら枠に置き換えて止めている（`app.py` の `X_MORNING_NEWS_POSTS` を True にすると戻る）。LINEのカードは今までどおり届く

### 朝の追加機能：くじら枠（`kujira_posts.py`）
アカウントの軸（株主優待・高配当）に合わせた投稿を、平日の朝に1本出す。曜日ごとに型を替える。
| 曜日 | 型 | 中身 |
|---|---|---|
| 月 | 整理 | 権利確定が近い月の、人気の優待まとめ（3銘柄・画像付き） |
| 火 | 今日の1銘柄（優待） | 1〜2ヶ月先に権利確定する人気の優待から1銘柄（画像付き） |
| 水 | 解説 | 配当・優待の見方（8テーマを週替わり。個別の銘柄は出さない。要点4つを並べた画像付き） |
| 木 | 今日の1銘柄（高配当） | 東証プライム・利回り3.5〜5.5%・時価総額1,000億円以上・配当性向10〜70%から1銘柄（画像付き） |
| 金 | 実体験 | 自分の売買・配当の記録。botでは作らず、夕方のLINEに書く型だけ送る（自動投稿しない） |

- 利回り・最低投資額・権利確定日などの数字は、Yahoo!ファイナンスの優待人気ランキング（月別）と配当利回りランキングのものをそのまま使う。AIに任せるのは言い回しだけ
- AIの文章に、材料に無い数字や銘柄が混ざっていたら、決まった型の文章に切り替える
- 「今日の1銘柄」は、同じ銘柄を45日間は出さない（`state.json` に記録）。今朝のニュース版・買い場候補版と同じ銘柄も出さない
- スプシの状況が「購入済」の銘柄を紹介するときは、投稿の最後に「※保有中の銘柄です」と書く（スプシが読めないときは付けられない）

### 朝の追加機能：ウォッチ銘柄の決算チェック（`earnings_watch.py`）
- スプシ「気になるテーマ株_一覧表」の「マスター」タブ（リンク共有・閲覧のみ）から銘柄を読む（状況が「見送り」は除く）
- 前営業日のTDnetに出た「決算短信」「業績予想の修正」「配当予想の修正」を拾い、PDFの1〜2ページ目をAIに要約させてLINEに1メッセージで送る（該当がない日は送らない）
- 要約の形：売上・営業益・経常・純利益の前年比／通期進捗率／通期予想の修正／配当の修正／一言。「購入済」の銘柄には★保有を付ける
- Variables の `WATCHLIST_SHEET_ID` が空のときは何もしない。スプシへの書き戻しはしない

### 朝・夕方の追加機能：株ニュース（`news_posts.py`）
- 会社の公式発表（TDnetの適時開示）から、株価に関わりそうなニュースを広く拾って、朝と夕方に1本ずつ投稿する（1社1論点・文字だけ。2026/11/22に3社・画像付きから変更）
  - 1行目に会社名と「何がどう変わったか」を数字つきで書き、続けて資料の中の別の数字を1つ取り上げて「でも僕が気になったのは〜」と自分の見方を書く
  - 拾う種類：優待の新設・拡充・変更・廃止、増配・減配、記念配当、自社株買い、業績予想の修正、TOB・MBO、株式分割、提携・M&A
  - 朝：前の回のあと〜今朝までの発表　／　夕方：今日の発表
  - 同じ発表は二度出さない（`state.json` に記録）。該当の発表が無い回は出さない
  - 選ぶ会社：時価総額ランキング上位300社（持っている人が多い会社）の中で、優待・配当・自社株買いのニュースを先にする。上位300社に無ければそのほかの種類、それも無ければ全体から選ぶ
- 発表のPDFの1ページ目をAIに読ませて、「何がどう変わったか」を一言にする。PDFに無い数字が混ざったら、決まった型の文章に切り替える
- **土曜の朝：今週のまとめ**　その週（月〜金）の発表を種類ごとに数えて1本にする（AIは使わない・画像付き）

### 日曜16:00：来週の予定（`week_ahead.py`・ネタ候補の回に相乗り）
- 来週（月〜金）の決算発表（JPXの予定表。日ごとの社数と主な会社、★はウォッチ・保有銘柄）、休場日、月末権利の権利付き最終日・権利落ち日、SQ
- AIは使わない（コスト0）。予定が1つも無い週は送らない

### 毎日16:00：徹底解説のネタ候補（`note_topics.py`・`topics.yml`）
- noteの「徹底解説」の記事用に、その日の時事ネタを5〜8個、トピックと簡単なサマリでLINEに送る（土日も）
- 材料：Claude APIのWeb検索（その日の株・経済ニュース）と、前日16:00以降〜その日の適時開示・相場の動き
- 最近14日に出したトピックは避ける（`topics_state.json` に記録）
- Web検索が使えないときは開示と相場だけで作り直し、それも無理ならその日の開示を並べて送る
- 各ネタに、徹底解説の構成案（見出し3つ）を付ける
- モデルは下の「AIのモデルと使いすぎ防止」のとおり
- 書くときは、Claudeで「note：トピック」と送る

### 平日10:00・13:00・18:00：Xのリプ案（`x_replies.py`・`replies.yml`）
- 自分あてのリプと、絡む候補（優待・高配当まわりの青バッジの人の投稿。1回5人、同じ人は1日1回まで、フォロワー3割）を拾い、Opusで返信案を作ってLINEにカードで送る
- Xには投稿しない。カードの「コピー」「返信する」から、自分で確かめて送る
- X APIの読み取りは月 `X_BUDGET_USD`（初期値40ドル）まで。超えそうならその月は止めてLINEで知らせる

### 毎日7:21ごろ・12:34ごろ・18:39ごろ：共感ポスト（`kyokan_posts.py`・`x_queue.yml` に相乗り）
- 読んだ人が「わかる」「自分はこう思う」と言いたくなる短い投稿。型は6種類（空気をひっくり返す／株クラあるある・一言／参加したくなる問いかけ／素朴な疑問／本音／仮の数字で見方を変える）で、続けて同じ型は出さない
- 投稿は `kyokan_stock.json` にストックしておき、予約投稿の回がその日の3本を並べる。出番待ちが9本を切ったら、AI（Opus）が15本作り足してLINEに一覧を送る
- 過去に作った投稿と文面が似ているもの、銘柄コード・大型株の社名・ハッシュタグ・URLが入ったもの、反応を頼む言い方（「教えてください」「リプで」「いいねして」「フォローして」「リポストして」「保存して」）が入ったものは、ストックに入れない
- 6つ目の「仮の数字で見方を変える」の型だけ、仮の数字（「仮に」「〜とする」など）を使える。ほかの型では数字が入っていたらはじく
  - この型は、チャットのスキル「投稿文作成」で作って検算したもの（`source: "chat"`）だけを入れる。botの作り足しでは作らない
  - 18:39ごろの枠は、ストックにこの型があれば先に出す
- すべての投稿の最後に `#株 #株クラ` を付ける（AIには書かせず、予約に並べるときにプログラムで付ける）
- チャットのスキル「投稿文作成」で作った投稿は `source: "chat"` で入れる。botが作ったものより先に出る
- 起動が遅れて 7:21ごろの回は 9:30、12:34ごろの回は 14:30、18:39ごろの回は 21:30 を過ぎたら見送り、その投稿はストックに戻す

### 毎日8:26ごろ・21:13ごろ：「〇万円あったら」／平日16時すぎ：大型株の値動き（`quick_posts.py`・`x_queue.yml` に相乗り）
- AIを使わない投稿。株価と配当のデータを、決まった型の文章に入れて作る（文字だけ・ハッシュタグなし）
- 「〇万円あったら」：持っている人が多い大型株（`WIDE` の38社）から、型を3つ回す（予算で何株買えるか／同じ予算で2社を比べる／配当で年〇万円ほしいなら何株か）。配当の金額は、今日の1銘柄と同じ置きかえ表で身近なものに置きかえる
- 大型株の値動き：38社のうち、今日いちばん動いた会社が ±2% 以上のときだけ1本出す（終値・100株の金額・利回り）
- 年間配当は yfinance の予想と実績の両方が取れて、差が35%以内・利回り0.8〜6.5%の会社だけ使う。投稿には「年間配当を1株〇円として」と計算の前提を書く
- スプシの状況が「購入済」の銘柄には、最後に「※保有中の銘柄です」と書く
- LINEには送らない（予約の記録は `x_queue.json`、その日に並べたかどうかは `quick_state.json`）

### 平日11:52ごろ・15:55ごろ：値下がりアラート（`price_alert.py`・`price_alert.yml`）
- 買いたい銘柄が下がったときに、LINEで知らせる（AIは使わない。Xには投稿しない）。知らせるものが無い回は送らない
- 対象：スプシ「気になるテーマ株_一覧表」の「Diego式」タブ（判定が「×」の銘柄は除く）と「成長株スクリーニング」タブ。スプシの銘柄を入れかえれば、対象もそのまま変わる
- 回数：昼休み（前場の終値）と、引け後（終値）の2回
- 知らせる条件
  | 条件 | 中身 |
  |---|---|
  | 急落 | 前日比 −8%以上（1銘柄につき1日1回）。日経平均の動きと、その日の適時開示のタイトルを添える |
  | 52週高値からの下げ | −10% / −15% / −20% の段階ごとに1回だけ |
  | 配当利回り（Diego式だけ） | 4.0% / 4.5% を超えたとき、段階ごとに1回だけ（スプシの1株配当 ÷ いまの株価） |
  | 相場全体の下げ | 日経平均が −3%以上の日に、対象銘柄の下げ幅ランキング（上位10）を1通（1日1回） |
- 「段階ごとに1回だけ」は、その段階から3ポイント（利回りは0.2ポイント）戻ると外れる。次に同じ段階まで下がったら、もう一度知らせる
- 初めて動いた回は、いまの位置（すでに −10%以下の銘柄、利回りが4.0%以上の銘柄）を送り、そこから先の変化だけを知らせる。あとからスプシに足した銘柄は、いまの位置を記録するだけで知らせない
- 株価は yfinance（Yahoo!ファイナンス。約20分遅れ）の、配当で調整していない値。その日の株価がまだ入っていなければ、あとの回でやり直す
- 起動の予約は1時間おき。起動できた回が 11:52 / 15:55 まで待つ。昼の分は14:30、引け後の分は次の日の8:30を過ぎたら見送る
- スプシを読めないとき（共有が「リンクを知っている全員・閲覧者」でない・タブ名が違う）は、1日1回だけLINEで知らせる。リポジトリに `alert_watchlist.json`（`[{"code": "5288", "name": "…", "groups": ["Diego"], "div": 70}]`）があれば、そちらを使う
- 手動実行（Run workflow）は、待たずにいまの株価で動く

### 夕方（平日 16:55 JST を目標に開始・祝日は休み）
- 朝の銘柄の当日の騰落（振り返り）
- 週の最終営業日：今週の成績（分類別・ベスト3／ワースト3）＋買い場候補の1週間後・1ヶ月後の成績
- 明日が権利付き最終日の優待銘柄のリマインド
- 明日決算の注目銘柄（JPXの決算発表予定表から。ウォッチ銘柄・最近配信した銘柄を優先。取れないときだけyfinanceで代用）
- 週の最終営業日：自分の売買・配当の記録を書くための型（LINEだけ。自動投稿しない）
- X下書き：なぜ動いたか／明日の決算予告／実績報告（週末のみ・成績グラフ画像付き）

### Xへの自動投稿
- Variables の `X_AUTO_POST` が `on` のときだけ投稿する。同じ回で2本以上出すときは30分間隔
- 出す時刻：朝の株ニュースは 6:50ごろ、くじら枠（火・木：今日の1銘柄／月：整理／水：解説）は昼 11:50ごろ、夕方は 17:05ごろから1時間おき（なぜ動いたか 17:05ごろ → 明日の決算 18:05ごろ → 株ニュース 19:10ごろ。週の最終営業日は実績報告 20:05ごろ）。無い投稿があれば、その分は前に詰める
- きりのいい分（:00・:05・:10…の5分きざみ）は予約っぽく見えるので出さない。もとの時刻を半端な分にしたうえで、日ごとに0〜8分ずらす（`x_queue.slot_time`。2026/11/22に変更）
- ハッシュタグは、すべての投稿で `#株 #株クラ` の2つ（2026/11/22に変更。「〇万円あったら」と大型株の値動きだけ、タグなしで試している）
- 1日の本数は、平日で最大11本（朝のニュース／共感ポスト3本／「〇万円あったら」2本／くじら枠／大型株の値動き／なぜ動いたか／明日の決算／夕方のニュース）
- くじら枠と夕方の2本目以降は、朝・夕方の回が文章と画像を作ってLINEに送り、時刻を付けて `x_queue.json` に並べる。出すのは予約投稿の回（`x_queue.py`・`x_queue.yml`）
- 予約投稿が遅れたとき：昼の分は13:30、夕方の分は22:00を過ぎたら見送ってLINEで知らせる。2本が重なったら30分あける
- URL入り（料金が約13倍）・NGワード（必ず上がる等）の下書きは投稿しない
- 失敗・スキップがあったときだけLINEで知らせる

### AIのモデルと使いすぎ防止（`ai.py`）
- すべてのAIの処理（銘柄選び・X投稿・夕方の解説・ネタ候補・優待の読み取り・決算要約）を `claude-opus-5-5` で行う。Haiku は使わない（Fable 5.2 は kujira-note に回している）
- Maxプランの月100ドルのAPIクレジットのうち、このbotの分を50ドルとしている（残りの50ドルは kujira-note の週次・月次・徹底解説の分）
- その月（毎月9日から）にこのbotで使った額が50ドルを超えたら、その月の残りは `claude-sonnet-5-5` に切り替える
- Opus が失敗したとき（使えない・混んでいるなど）も、その回だけ Sonnet でやり直す
- 銘柄選びとネタ候補は考える量を多め（effort=high）、ほかは普通（medium）
- 夕方の「なぜ動いたか」は、値動きランキングの上位10銘柄の理由をWeb検索で確かめてから書く

### 定時実行のずれ対策
GitHub Actionsの定時実行は、数時間遅れることが多い（2026/11の実績：5〜9時間遅れ。6時間前からの予約では間に合わなかった）。そのため次の形にしている。
- 起動の予約を、目標の12時間前から1時間おきに入れる（朝 前日18:43〜6:43、夕方 4:55〜16:55、ネタ候補 4:03〜15:58）。Xの予約投稿の回は1日じゅう1時間おき
- 目標より早く起動できた回は、目標の時刻まで待ってから動く。5時間以上早い回は何もしないで終わる（1回の起動は6時間までなので、待てるのは5時間）
- その日の配信が済んだら `state.json` に記録し、あとの回は何もしないで終わる（二重配信しない）
- 起動が遅すぎた回（朝 8:55より後、夕方 22:00より後）は、LINEには送るが、Xには自動投稿しない
- 夕方の回が日付をまたいで起動したら、前の日の分として動く（以前は翌日の扱いになり、金曜の振り返りが「休場日」として消えていた）
- 手動実行（Run workflow）は、待たずにすぐ動く。Xにも投稿する

### Notionへの転記（`notion_log.py`）
- LINEに送った内容を、Notionの「LINE株botログ」DBにも転記する。1日＝1ページ（名前「11/17(火)の配信」・日付・件数）
- ページの中は1通＝1つのトグル。見出しは「06:45 朝｜1行目」（種類：朝／夕方／ネタ候補／来週の予定／⚠️ 通知）
- トグルの中は1行＝1つの箇条書き。X下書き（最後の行がハッシュタグのもの）はコピペしやすいよう普通の文章のまま。画像はその下に付ける
- DBは `NOTION_PAGE_ID` のページの中に初回に自動で作る。`NOTION_TOKEN` と `NOTION_PAGE_ID` が無いときは何もしない。転記に失敗してもLINEの送信やbotは止めない

## 設定
### Secrets（Settings → Secrets and variables → Actions → Secrets）
| 名前 | 用途 |
|---|---|
| `LINE_ACCESS_TOKEN` | LINE Messaging API のチャネルアクセストークン |
| `USER_ID` | LINEの送り先（自分のユーザーID） |
| `ANTHROPIC_API_KEY` | Claude API（Haiku 4.5） |
| `X_API_KEY` / `X_API_SECRET` | X のコンシューマーキー（OAuth 1.0a） |
| `X_ACCESS_TOKEN` / `X_ACCESS_TOKEN_SECRET` | X のアクセストークン（Read and write で発行したもの） |
| `NOTION_TOKEN` | Notionの連携（インテグレーション）のトークン（任意） |
| `NOTION_PAGE_ID` | 転記先のNotionページのURLかID。連携をこのページに接続しておく（任意） |

### Variables（同じ画面の Variables タブ）
| 名前 | 用途 |
|---|---|
| `X_AUTO_POST` | `on` で X に自動投稿。止めるときは `off` |
| `AI_MODEL` | 使うモデル。空なら `claude-opus-5-5` |
| `BUDGET_USD` | このbotで1ヶ月に使ってよい額（ドル）。超えたら `claude-sonnet-5-5` に切り替える。空なら 50 |
| `X_BUDGET_USD` | リプ案の X API 読み取りの月の上限（ドル）。超えそうならその月は止める。空なら 40 |
| `CREDIT_DAY` | APIクレジットが入る日（月の何日か）。使用額はこの日から数え直す。空なら 9 |
| `IMAGE_THEME` | 画像の配色。空ならミッドナイト×金（noteと同じ）。前の白いカードに戻すなら `gold_solid` |
| `WATCHLIST_SHEET_ID` | ウォッチ銘柄のスプシのID（URLの `/d/` と `/edit` の間）。スプシは「リンクを知っている全員が閲覧可」にしておく |
| `ALERT_DROP_PCT` | 値下がりアラートの「急落」の基準（前日比の下げ％）。空なら 8 |
| `ALERT_DD_LEVELS` | 52週高値からの下げの段階（％）。空なら `10,15,20` |
| `ALERT_YIELD_LEVELS` | 配当利回りの段階（％。Diego式だけ）。空なら `4.0,4.5` |
| `ALERT_MARKET_PCT` | 「相場全体の下げ」の基準（日経平均の下げ％）。空なら 3 |
| `ALERT_DIEGO_SHEET` / `ALERT_GROWTH_SHEET` | 対象を読むタブの名前。空なら「Diego式」「成長株スクリーニング」 |

### コード内の主な設定
- AIモデル：`claude-haiku-4-5`（Web検索は使わない）
- 画像の配色：`IMAGE_THEME`（初期値 `midnight`＝ミッドナイト×金・明朝体の題字。noteの画像とそろえている）
- 目標の時刻と、Xを見送る時刻：`TARGET_TIME` / `X_DEADLINE`（`app.py`）
- くじら枠の曜日割り・ハッシュタグ・高配当の条件：`PLAN` / `HASHTAGS` / `HAITO_*`（`kujira_posts.py`）
- Xの投稿間隔：`X_POST_INTERVAL_MIN = 30`
- Xのハッシュタグ：`X_HASHTAGS_MORNING`（朝）／`X_HASHTAGS_EVENING`（夕方）／各ファイルの `HASHTAGS`。どれも `#株 #株クラ`
- 出す時刻のもと：`FIRST_POST_BASE`（`app.py`）／`MIDDAY_BASE`・`EVENING_BASES`・`JITTER_MIN`（`x_queue.py`）／`SLOTS`（`kyokan_posts.py`）／`YOSAN_SLOTS`・`UGOKI_BASE`（`quick_posts.py`）

## 料金の目安
- Claude API：朝 月400円前後＋夕方 月15〜100円（ログの「API料金（推定）」で確認できる）
- X API：従量課金。普通の投稿 $0.015／件、URL付き $0.20／件（URLは入れない運用）。平日は1日最大11本、土日は6本前後で、月300本前後（約4.5ドル）
- GitHub Actions：公開リポジトリなので、待ち時間が長くても無料
